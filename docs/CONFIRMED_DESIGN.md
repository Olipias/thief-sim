# 用户确认方案：独立场景、安全屋与交易

确认日期：2026-11-16。状态：**设计已确认，待实现**。本次只授权同步文档，不授权开始实现，也不生成或替换标题封面。

本文件是后续 agent 的当前设计入口。与 GDD.md 同步；READMEnew.md、旧 GDD、剧情圣经、美术提案、旧任务板中的冲突内容均已被本次用户裁定取代。代码和测试用于确认“目前实际做了什么”，不能用来否定已确认的新需求。旧版测试全绿和构建可启动不代表以下设计已实现或试玩合格。

## 1. 必须更换的旧流程

删除正式流程中的旧 Hub 栏目选择页，包括任务、商店、销赃、推理等顶部入口。不能只改标题、隐藏部分按钮或用安全屋背景遮住旧页面。

新游戏流程：

**标题 → 签约分镜 → 自动进入青铜人面具教学 → 撤离回独立安全屋 → 手机接任务、实体电脑调查 → 手机选择并确认行动 → 走到房门出发 → 博物馆 → 带回文物进入安全屋 → 剧情交付或普通交易。**

继续游戏回到合法检查点，不强制重播签约或教学。切关、失败返回、撤离、结局回溯、读档均不得重新进入旧栏目页；也不在教学后插入独立结算/任务选择页面。

## 2. 签约分镜与直白剧情

- 分镜交代主角处境、如何遇到恶魔并签约、恶魔的要求与违约风险、为什么第一单是青铜面具；分镜结束自动接教学。
- 点击、E、空格均可推进：本页字幕未显示完时第一次操作显示全文，再次操作切下一格。单独提供“跳过开场，进入教学”。同一次输入不能跨过多格或穿透为教学中的拾取/移动。
- 不再按每格18秒强制等待。原2–3分钟仅作为正常阅读和演出节奏参考，不得作为最低停留时间；144秒实测只记录旧版行为。
- 剧情语言直白易懂，不用缺乏上下文的隐喻、人名或地址推动任务。每个节点必须清楚说明谁在说话、为何联系主角、要求是什么、接下来去哪里/做什么。
- 教学撤离用简短过场解释返回住处。来电说明下一单，电脑调查解释候选文物和接洽方；对方首次出现要说明身份、目的与接收方。
- 分支保持明确代价，不出现“正确答案”提示；恶魔可有压迫感，任务与后果不能含糊。

## 3. 安全屋是可走动的独立室内场景

像《星露谷》进屋一样，进入单独的俯视角2D像素房间：角色可走动，有墙体/家具碰撞与接近交互。不是纯UI信息页，也不要求运行时3D建模。

| 房内对象 | 职责与交互 |
| --- | --- |
| 书桌上的实体电脑 | 走近按E使用，坐下/进入电脑界面；退出回到桌旁，恢复房间操作 |
| 手机 | P打开应用首页；负责委托、行动准备、交易联系、联系人和日历 |
| 文物箱 | 走近按E打开，存入/取出文物，查看名称、图片、任务或交易状态 |
| 房门 | 手机确认行动后由此出发；买家到来时由此交货；未准备时明确提示 |
| 床、窗户、普通家具 | 构成住处与少量查看互动，暂不扩展为生活模拟系统 |

手机、电脑、箱子均是房间内的交互覆盖层，关闭后留在原房间位置。世界节点仍挂默认世界层，UI才使用CanvasLayer。一次只处理一个主要交互，上层关闭后不应误触开门或再次打开面板。

## 4. 手机应用与出发

首页使用应用图标，不能复制旧Hub顶部栏目页。

| App | 功能 |
| --- | --- |
| 委托 | 查看任务要求、调查进度、已解锁目标；选择目标并确认“准备出发” |
| 交易 | 查看箱内普通文物报价、批量预约/取消、买家到达与交货进度 |
| 联系人 | 恶魔、线人、对应国家接洽方与普通买家，来电对话和联络记录 |
| 日历 | 闭馆/维护/事件记录；虚构排期和真实史实明确区分 |

手机选任务不会立刻切场景。选定并确认后，关闭手机，走到门口按交互出发。未解锁目标不可出发，三条证据链全部完成再开放三件主要目标选择。电脑负责调查，手机显示进度与安排，不自动替玩家拼线。

## 5. 实体电脑与文物箱

电脑内保留浏览器、档案库、邮件、聊天和手动拖卡连线推理板。必须从房内书桌进入，不作为场景顶部标签。调查和任务指令以直白语言衔接，区分史实与游戏安保/接洽虚构。

箱子界面左右分别是“随身携带”和“箱内存放”；选择即可转移，不做复杂格子拼装。初版箱子不限容量。允许一次取出全部预约物品，减少往返。

物品显示名称、图片和状态（例如待交付/已预约）。存放或取出不能复制物品、清除任务归属或改变其文物身份；主线文物存箱后仍可触发催交并继续剧情。

## 6. 普通文物：存箱 → 手机预约 → 取货 → 门口交付

1. 带回普通文物，存入箱子。
2. 手机交易App读取箱内可售物品，展示物品、买家、报价，可批量预约。
3. 确认预约时不扣物品、不付钱；物品标记预约状态，不能重复预约。
4. 手机通知买家到达，同时敲门；门外神秘人等待交货，不设置等待倒计时或罚款。
5. 玩家从箱中取出预约物品，到门口选择交货；可以一次取出、一次交付多件。
6. 展示交货清单与金额，玩家确认后才移除实际物品并支付钱款，买家离开。

缺少预约物品时明确提示缺什么，不吞物品、不扣钱。允许取消预约并释放状态。门口出发与交货必须有明确选择，不能误卖或误切关。保存、重开、重复点击、离开再回来都不能重复发钱；交货必须作为一次完整结算执行。

保留普通文物收集与出售；原“本作完全没有普通杂物交易”限制已被用户取代。一次行动只选一个主要目标，不可据旧单件目标限制禁止所有普通文物。普通携带容量由对应实现任务确定，不恢复复杂拼格成长循环。

## 8. 确定性预演与全世界暂停

| 状态 | 玩家 | 守卫、监控与世界计时 |
| --- | --- | --- |
| 规划 | 完全不能移动、自动移动、拾取、交互或改变世界；只编辑路线 | 巡逻、调查、追击、视野方向、监控、噪音寿命、行动计时均冻结 |
| 执行/手动接管/取消规划 | 自动沿路线或正常手动控制 | 全部一起恢复，按真实位置正常发现与追踪 |

技术约束和首个灰盒里程碑见[确定性预演](DETERMINISTIC_PREVIEW.md)：固定tick、共享模拟内核、完整快照、逐tick一致、无执行时随机偏移。预演使用快照副本，执行从同一快照开始；失败恢复完整起始快照并保留原路线，手动接管后原预测失效。

进入规划前保留世界状态，不能每次开关就重置守卫巡逻、警觉或追击进度。显示“规划中：人物与时间暂停”。覆盖层打开、关闭、路线完成、取消、接管、失败重试、切场景均由统一状态转换恢复正确行为，不可出现玩家走动但守卫仍冻结。反复开关规划不能获得免疫或永久定身。

## 9. 文本与标题UI

- 对话正文固定宽度、自动换行、过长分页；每页一个意思。不缩小字体硬塞。教学后画面、长物品名、选择按钮和所有设备页面均在640×360内检查。
- 用户已指定标题封面为 `assets/art/CPy0UzlakIPj0kfwMuVCR.png`（1376×768）。后续标题UI使用这张图适配；本次仅登记，不生成、不改图、不替换游戏资源引用。
- 标题目标氛围：神秘、帅气；按钮清楚可用，字体、颜色、间距与游戏统一。不要继续使用依封面人物手部/建筑入口散落的按钮布局。
- 标题菜单集中固定排列：继续游戏、新游戏、设置、制作人员与声明、退出游戏。有效存档突出继续；覆盖旧档需确认。不放金币、任务卡、商店或技术性存档信息。
- 游戏内交互提示、对话、手机、电脑、箱子统一视觉规则，各自用途明确。
