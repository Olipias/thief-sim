# 决策记录（DECISIONS，ADR-lite）

> 用途：记录「为什么这样做」，防止未来 agent 无意推翻。
> 规则：新决策在文件末尾追加编号；**不改写历史条目**；如需推翻，新增一条并注明「取代 D-xxx」。
> 本文件前 10 条为 2026-10-14 从现有代码与 CHANGELOG 整理（非新决策），并在维护体系建立时固化。

---

## D-001 引擎与渲染基线
- 状态：已生效
- 决定：Godot 4.7；`gl_compatibility` 渲染；逻辑分辨率 640×360；窗口整数缩放（1280×720）；纹理最近邻过滤；中文像素字体 Fusion Pixel 12px（OFL）。
- 原因：像素画面清晰稳定；兼容性优先（低端设备/无独显可跑）。
- 影响：所有贴图按 16px 网格与整数缩放设计；UI 布局不得假设大于 640×360 的显示面积。

## D-002 全局状态集中在 Game 单例
- 状态：已生效
- 决定：金钱/背包/升级/存档/任务判定全部收进 `Game`（`src/autoload/game_state.gd`）；音效独立为 `Audio`。
- 原因：规则单点、UI 只读 + 监听信号，纯数据便于单测（测试可直接 `new()` 后调用）。
- 影响：不要在 UI/actor 里复制规则逻辑；改行为先改 `Game` 并补 `test_logic` 用例。

## D-003 世界节点不得挂到 CanvasLayer 下（相机教训）
- 状态：已生效（v0.6.0 修复过同类问题）
- 决定：世界（Museum/Hub 等）挂在 `main.tscn` 的默认画布 `Screen`；UI 才用 CanvasLayer。
- 原因：CanvasLayer 内的相机不作用于该层渲染——曾导致 Camera2D 静默失效，旧地图小到看不出。
- 影响：任何"把世界包一层"的重构都要重新验证相机 limit 生效（冒烟测试 `_test_room_camera` 守这一点）。

## D-004 单屏一房间 + 相机按房间锁定
- 状态：已生效
- 决定：地图由若干 20×12 房间蛇形串联，一次只见一屏；进房间切换相机 limit；感知（噪音/哀嚎）按房间分流。
- 原因：警察位置不一览无余，制造逐间探索的张力；每屏内容密度可控。
- 影响：改地图/房间数会同时影响相机、小地图、测试断言（见 ARCHITECTURE §6.2）。

## D-005 占位资源生成管线
- 状态：已生效
- 决定：美术与音效由 `tools/gen_*.py` 程序生成；关卡 JSON 由 `tools/gen_museum_map.py` 生成（自带结构校验）；生成物提交进仓库但**禁止手改**。
- 原因：无美术资源时保持可玩与可迭代；脚本可重复生成、可 diff、可程序化校验。
- 影响：改素材 = 改脚本 + 重新生成；`tools/check_level.py` 在 verify 中校验地图与脚本同步。

## D-006 测试策略
- 状态：已生效
- 决定：三类测试——纯逻辑（SceneTree 脚本）、场景冒烟（真实场景跑行为）、截图（人工核验画面）；测试存档隔离 `/tmp`；测试与退出前 `Audio.shutdown()`；所有测试非零退出码 = 失败。
- 原因：无 CI 环境下，agent 需要可脚本化、可断言的「完成信号」。
- 影响：新增功能必须补对应类别测试；「假泄漏」告警由 shutdown 规避，不要靠忽略警告解决。

## D-007 版本与变更记录流程
- 状态：已生效
- 决定：原型期版本号 `v0.x.0` = 一批功能，`v0.x.y` = 修复/杂项；每批改动更新 CHANGELOG（含日期与分类）+ README 进度。
- 原因：课程提交需要可追溯的版本轨迹；多窗口协作需要"改了什么、为什么"的记录。
- 影响：收尾流程见 AGENTS.md「完成定义」；纯工程维护批次记为 `v0.x.y`（如 v0.8.1），并在 CHANGELOG 中标明「不改变游戏行为」。

## D-008 任务完成判定实时推导
- 状态：已生效
- 决定：`mission_complete` 每次背包变动实时重算；目标物离开背包 → false → 出口重新上锁。
- 原因：避免"丢出目标仍可撤离"的漏洞；规则天然一致（无历史状态位）。
- 影响：不要引入「曾经拿到过」之类的缓存标记。

## D-009 内容表暂存在代码中（技术债）
- 状态：现状（计划迁移）
- 决定：`CATALOG / SHAPES / UPGRADES / BAG_SIZES` 暂时是 `game_state.gd` 的 const 字典。
- 原因：单关卡原型期规模小，常量直接出现在代码里改起来最快（有 `test_content.gd` 守一致性）。
- 影响：加内容必须改代码 —— 这是已知技术债；数据化迁移列入 ROADMAP（M4），迁移时同步升级 `test_content.gd` 为 schema 校验。

## D-010 可测性优先的写法：纯函数与信号
- 状态：已生效
- 决定：关键几何/判定做成静态纯函数（如 `Police.in_cone`）；跨模块通信走信号（`backpack_changed`、`wailed`、`escaped` 等），由 `main.gd` 编排。
- 原因：纯函数可单测；信号解耦 UI 与世界，避免相互引用导致的回归。
- 影响：新增判定优先写纯函数 + 用例；新增模块间通信优先用信号，不要跨层 `get_node` 取对方内部状态。
