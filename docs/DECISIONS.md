# 决策记录（DECISIONS，ADR-lite）

> 用途：记录「为什么这样做」，防止未来 agent 无意推翻。
> 规则：新决策在文件末尾追加编号；**不改写历史条目**；如需推翻，新增一条并注明「取代 D-xxx」。
> 本文件前 10 条为 2026-10-14 从现有代码与 CHANGELOG 整理（非新决策），并在维护体系建立时固化。

---

## D-001 引擎与渲染基线
- 状态：已生效
- 决定：Godot 4.7；`gl_compatibility` 渲染；逻辑分辨率 640×360；窗口整数缩放（1280×720）；纹理最近邻过滤；中文像素字体 Fusion Pixel 12px（OFL）。
- 原因：像素画面清晰稳定；兼容性优先（低端设备/无独显可跑）。
- 影响：所有贴图按 16px 网格与整数缩放设计；UI 布局不得假设大于 640×360 的显示面积。

## D-002 全局状态集中在 Game 单例
- 状态：已生效
- 决定：金钱/背包/升级/存档/任务判定全部收进 `Game`（`src/autoload/game_state.gd`）；音效独立为 `Audio`。
- 原因：规则单点、UI 只读 + 监听信号，纯数据便于单测（测试可直接 `new()` 后调用）。
- 影响：不要在 UI/actor 里复制规则逻辑；改行为先改 `Game` 并补 `test_logic` 用例。

## D-003 世界节点不得挂到 CanvasLayer 下（相机教训）
- 状态：已生效（v0.6.0 修复过同类问题）
- 决定：世界（Museum/Hub 等）挂在 `main.tscn` 的默认画布 `Screen`；UI 才用 CanvasLayer。
- 原因：CanvasLayer 内的相机不作用于该层渲染——曾导致 Camera2D 静默失效，旧地图小到看不出。
- 影响：任何"把世界包一层"的重构都要重新验证相机 limit 生效（冒烟测试 `_test_room_camera` 守这一点）。

## D-004 单屏一房间 + 相机按房间锁定
- 状态：已生效
- 决定：地图由若干 20×12 房间蛇形串联，一次只见一屏；进房间切换相机 limit；感知（噪音/哀嚎）按房间分流。
- 原因：警察位置不一览无余，制造逐间探索的张力；每屏内容密度可控。
- 影响：改地图/房间数会同时影响相机、小地图、测试断言（见 ARCHITECTURE §6.2）。

## D-005 占位资源生成管线
- 状态：已生效
- 决定：美术与音效由 `tools/gen_*.py` 程序生成；关卡 JSON 由 `tools/gen_museum_map.py` 生成（自带结构校验）；生成物提交进仓库但**禁止手改**。
- 原因：无美术资源时保持可玩与可迭代；脚本可重复生成、可 diff、可程序化校验。
- 影响：改素材 = 改脚本 + 重新生成；`tools/check_level.py` 在 verify 中校验地图与脚本同步。

## D-006 测试策略
- 状态：已生效
- 决定：三类测试——纯逻辑（SceneTree 脚本）、场景冒烟（真实场景跑行为）、截图（人工核验画面）；测试存档隔离 `/tmp`；测试与退出前 `Audio.shutdown()`；所有测试非零退出码 = 失败。
- 原因：无 CI 环境下，agent 需要可脚本化、可断言的「完成信号」。
- 影响：新增功能必须补对应类别测试；「假泄漏」告警由 shutdown 规避，不要靠忽略警告解决。

## D-007 版本与变更记录流程
- 状态：已生效
- 决定：原型期版本号 `v0.x.0` = 一批功能，`v0.x.y` = 修复/杂项；每批改动更新 CHANGELOG（含日期与分类）+ README 进度。
- 原因：课程提交需要可追溯的版本轨迹；多窗口协作需要"改了什么、为什么"的记录。
- 影响：收尾流程见 AGENTS.md「完成定义」；纯工程维护批次记为 `v0.x.y`（如 v0.8.1），并在 CHANGELOG 中标明「不改变游戏行为」。

## D-008 任务完成判定实时推导
- 状态：已生效
- 决定：`mission_complete` 每次背包变动实时重算；目标物离开背包 → false → 出口重新上锁。
- 原因：避免"丢出目标仍可撤离"的漏洞；规则天然一致（无历史状态位）。
- 影响：不要引入「曾经拿到过」之类的缓存标记。

## D-009 内容表暂存在代码中（技术债）
- 状态：现状（计划迁移）
- 决定：`CATALOG / SHAPES / UPGRADES / BAG_SIZES` 暂时是 `game_state.gd` 的 const 字典。
- 原因：单关卡原型期规模小，常量直接出现在代码里改起来最快（有 `test_content.gd` 守一致性）。
- 影响：加内容必须改代码 —— 这是已知技术债；数据化迁移列入 ROADMAP（M4），迁移时同步升级 `test_content.gd` 为 schema 校验。

## D-010 可测性优先的写法：纯函数与信号
- 状态：已生效
- 决定：关键几何/判定做成静态纯函数（如 `Police.in_cone`）；跨模块通信走信号（`backpack_changed`、`wailed`、`escaped` 等），由 `main.gd` 编排。
- 原因：纯函数可单测；信号解耦 UI 与世界，避免相互引用导致的回归。
- 影响：新增判定优先写纯函数 + 用例；新增模块间通信优先用信号，不要跨层 `get_node` 取对方内部状态。

## D-011 定位调整：叙事优先，警察从常态巡逻改为事件驱动
- 状态：已生效（方向，随 M5 逐步落地）
- 决定：游戏重心从「追逃」转向**叙事潜入**——博物馆平时安静，危险来自玩家触发的事件（警报展品、撬锁/破柜、摄像头、噪音阈值、剧情作祟）；警察系统保留但改为「触发器 + 岗哨 + 警戒等级（L0 平静/L1 搜索/L2 追捕/L3 封锁）」驱动。内容主体为**文物志**（幽灵讲述的文物专属剧情，结构参考《哑舍》：每件文物一个"志"，分初见/深入/结局三段）与组织角色剧情。
- 原因：最初设想即 3D 第一人称、馆内无巡逻、只在触发后被抓；2D 化是美术与性能的妥协，不应改变玩法重心。数位历史 capstone 的叙事与史料表达优先于纯追逃强度。
- 影响：
  - `police.gd` 状态机复用为事件响应，不做重写；新增「关卡危险配置」数据（触发器/岗哨/警报规则）。
  - 「贪心惩罚」方向改为负重减速（评估见 ROADMAP M5），**待 P3 事件化之后实施**。
  - 剧情 flag 与角色信任值需要进存档（遵守只增字段 + 默认值约定）。
  - 闪回插叙等叙事表现复用现有 UI 层模式（CanvasLayer + main 编排），不新增世界层节点类型。

## D-012 多关卡：注册表 + 生成器多配置 + 任务目标按关卡
- 状态：已生效（v0.9.0）
- 决定：关卡在 `Game.LEVELS` 注册（id/名称/地图/目标文物/报酬）；`Game.set_level()` 设定 `current_level_id` 与 `mission_target_id`；任务判定实时对照 `mission_target_id`（沿用 D-008 的推导原则，不新增"本关目标"状态位）。地图仍全部由 `tools/gen_museum_map.py` 的 `LEVELS` 配置生成，一个关卡一份 JSON；`check_level.py` 逐关卡校验生成物同步。Hub 以按钮选关（暂不做解锁进度）。
- 原因：第二关卡（大英博物馆）落地时最小改动地支持"不同关卡不同目标"；生成器复用同一套房间骨架与校验，避免复制粘贴第二份地图代码。
- 影响：
  - 新关卡 = 生成器加配置 + `Game.LEVELS` 登记 + （可选）专属简报；文物目标必须 `is_target=true` 且被关卡引用（`test_content` 双向校验）。
  - 真实文物目标必须先在 `docs/SOURCES.md` 登记（S-001 双羊尊为第一个）。
  - `CATALOG.is_target` 语义 = "是某个关卡的任务目标"，不再是"唯一目标"。

## D-013 3D 素材只在构建期使用，运行时保持纯 2D- 状态：已生效（v0.10.0）
- 决定：3D 模型（`assets/models/*.blend|glb`）**不进入游戏运行时**——`assets/models/` 放 `.gdignore` 由 Godot 完全忽略；需要 3D 资产的地方（目前是任务目标「商代双羊尊」）走离线渲染管线：Blender headless 渲染转台序列 → `tools/gen_relic_sprite.py` 像素化 → 产出 `assets/sprites/relic_<id>_strip.png`（转台动画条）与 `artifact_<id>.png`（图标）。渲染尺寸/帧数常量同时存在于生成脚本与 `Artifact`（`test_content` 校验一致）。
- 原因：2D 像素游戏混入运行时 3D 会带来渲染/性能/风格一致性问题；离线渲染能保留 3D 模型的形体精度又完全契合像素管线；同时为将来「文物档案 3D 化」保留了模型资产。
- 影响：
  - 改 3D 形体 = 改 `tools/blender/*.py` 重新生成模型 → 重跑渲染与像素化（生成物禁止手改）。
  - 新增"3D 化"文物 = 复用配方（ARCHITECTURE §6.7）；运行时代码无需改动（`artifact.gd` 自动识别转台条）。
  - 3D 属演绎性再现，学术口径仍以 `docs/SOURCES.md` 为准（模型说明须注明"非考古复原"）。

## D-014 文物志：史实走展签卡、演绎走器灵台词（文本数据独立）
- 状态：已生效（v0.14.0，落地 `docs/ARTIFACT_SYSTEM_PROPOSAL.md` 的 A+B 预案）
- 决定：文物的历史内容与叙事**分载体**呈现——**史实一律走「展签卡」**（米白纸卡 + 金线 + SOURCES 来源行），**器灵台词一律属虚构演绎**（深色对话框）；两者在视觉上不可混淆。文物志文本集中在 `src/data/lore.gd`（剧本 speech/card/choices/label/goto、展签卡、端详热点），运行时进度 `Game.lore_stage` / `lore_found` 进存档（只增字段 + 默认值）。
- 原因：数位历史专业的核心要求是"史实可考、演绎可辨"；把两者混在一段文字里会模糊边界。文本独立成文件同时避免多窗口争用 `game_state.gd`。
- 影响：
  - 新增文物志 = 改 `lore.gd` + 在 `docs/SOURCES.md` 登记（真实文物强制）+（可选）48×48 特写图。
  - 展签卡解锁与对谈进度绑定（第 i 张卡在第 i+1 段后解锁）；端详热点发现数计入存档。
  - `test_content` 校验剧本条目类型、卡片/热点字段、跳转与引用自洽；`test_logic` 校验进度上限与存档往返。

## D-015 关卡公平性：巡逻避开门口 + 教学关放宽警觉
- 状态：已生效（v0.14.1，试玩反馈驱动）
- 决定：把"进门不被手电照脸"做成**生成器强制的规则**——巡逻路线（含线段采样点）与同房间「门口相邻格」的距离必须 ≥ 3.5 格，违规则 `gen_museum_map.py` 生成失败（`check_level` 在 verify 中覆盖）。同时教学关（城西博物馆）通过 `Police.spot_delay_scale = 1.6` 放宽发现速度，大英博物馆保持 1.0。
- 原因：教学关应当教会"观察—等待—通过"，而不是进门就被抓（试玩反馈：第二个房间进门直面警察灯光，容错太低）。把规则写进生成器可防止后续改图时回归。
- 影响：改地图/巡逻时必须满足该规则；新增关卡默认同样受约束（如需"守门"设计，应通过剧情事件而非初始巡逻实现）；守卫反应速度成为可按关卡调参的字段（`spot_delay_scale`），调参不要写死进 police.gd。

## D-016 游戏内文本保持世界观叙述；正式声明集中到标题页
- 状态：已生效（v0.15.0）
- 决定：游戏内（任务终端、展签卡、端详）只保留**世界观内**的叙述与「档案 / 器灵」口吻，不显示来源引用、S 编号、「史实 / 演绎」等学术标注；所有正式声明（项目性质、史实与虚构分界、真实文物来源、3D 模型说明、字体许可、法律立场、致谢）集中在标题界面的「声明与说明」（`src/data/statements.gd` + `src/ui/statements_screen.gd`）。
- 原因：学术化抬头会打断沉浸感，不符合游戏文本；但数位历史项目仍需要可追溯的声明与来源，故集中放置、随时可查。
- 影响：新增真实文物时，除 `docs/SOURCES.md` 外还要在 `statements.gd` 的声明里补充（内容测试会校验声明覆盖真实文物）；游戏内文本不得出现来源路径 / S 编号（`test_content` 校验卡片不含 SOURCES）。

## D-017 互动特写层（2.5D）：高精度只出现在「触碰文物」这一层
- 状态：已生效（v0.16.0）
- 决定：有 `assets/sprites/relic_<id>_closeup.png` 的文物，玩家按 E 先进入互动特写层（黑场淡入、暖光、缓慢呼吸推近、显示文物名与故事），再按 E 拾取 / Esc 离开；打开期间游戏暂停。普通文物仍直接拾取。特写图由 3D 管线离线渲染（`render_relic_turntable.py` 新增机位 → `gen_relic_sprite.py` 输出），不在运行时加载 3D。
- 原因：落实 `docs/ART_DIRECTION.md` 的两层规则（常态全像素 / 互动后高精度），既保持像素玩法的统一，又让重点文具有「国宝」级的呈现；同时把特写与拾取动作绑定，避免"看一眼就自动拾取"。
- 影响：新增"特写级"文物 = 渲染 `relic_<id>_closeup.png`（3D 管线或手绘大图）；`Artifact.has_cinematic_closeup()` 自动识别，无需改关卡代码。特写层属于覆盖层契约（打开⇔暂停、E/Esc），输入流测试覆盖。

## D-018 战利品不自动出售：结算只发组织报酬，玩家在据点决定
- 状态：已生效（v0.16.0）
- 决定：成功撤离时任务目标上交、组织报酬自动入账；其余带出的文物全部进入 `Game.loot_stash`（据点仓库），由玩家在据点「销赃」页逐件或一次性卖出。失败被捕：赃物没收，仓库不变。
- 原因：让"偷什么、带多少、卖不卖"成为玩家的选择，并与背包取舍、后续「归还」分支衔接；自动出售会让这些选择失去意义。
- 影响：`finish_run` 不再累计战利品价值；结算界面只报告"已入库 + 估值"；仓库加入存档（只增字段）；新增测试覆盖入库/卖出/脏档/随机操作不变量。

## D-019 器灵哀嚎必须「可读、可反制」
- 状态：已生效（v0.16.2）
- 决定：器灵哀嚎时绘制扩散波纹；第一次真的引来警察时用 toast 说明原因与应对；与器灵交谈（E）会安抚它 8 秒（期间不哀嚎、不引警）；被哀嚎引来的警察停在约 2.5 格外搜索，而不是走到玩家脚下。警察发现过程在头顶显示黄色警觉进度条，发现延迟 0.5s（教学关 1.6×）。
- 原因：试玩反馈「拿完双羊尊站着不动，几秒后两名警察突然冲过来」——机制本身是设计意图（器灵是骚扰源），但玩家看不到因果、也没有反制，会被误判为 bug/隐藏惩罚。潜行游戏的惩罚必须建立在玩家可观察、可操作的信息上。
- 影响：`Ghost.calm(seconds)` 成为「交谈」的机械回报，也把玩家推向文物故事；`Police.investigate()` 新增 `stop_distance` 参数；新增/调整冒烟测试与视觉基线。今后新增「环境骚扰」类机制都必须同时提供：世界内可见的触发反馈、一次明确提示、至少一种反制手段。

## D-020 双羊尊 3D 呈现：默认混元 3D 资产，程序化模型作回退
- 状态：已生效（v0.17.0）
- 决定：离线渲染默认加载项目作者用**腾讯混元（Hunyuan3D）**生成的 3D 资产（`assets/models/e6b392….glb`，50 万面 + 4K PBR），归一化到程序化模型的尺寸/原点后复用同一影棚；`MODEL=procedural` 或资产缺失时退回程序化模型。原始 GLB **不入库**（`.gitignore`），仓库只包含渲染产物；小尺寸精灵做青铜绿色调分级，2.5D 特写保留 4K 贴图质感；渲染时压低镜面高光（Specular IOR Level 0.25）。
- 原因：程序化模型在特写层明显粗糙；混元 3D 资产的纹饰/羊首细节更接近馆藏实物，且离线渲染不增加运行时成本。
- 影响：重建资产需要该 GLB 在本地；没有它的环境仍可完整跑测试（回退模型）。资产由腾讯混元生成，再分发/商用需遵循其条款（当前仓库只分发派生的精灵图）。

## D-021 标题页用「场景化菜单」而不是左侧竖栏
- 状态：已生效（v0.18.0）
- 决定：标题页以整幅立绘为舞台，把主行动（开始/继续）放在角色按着的手边，商店放在博物馆正门台阶上，声明/退出缩在右下角；配入场淡入、盖章、按钮浮起、悬停放大与呼吸光框。商店按钮直接进据点商店页。
- 原因：竖栏列表把立绘降级成背景；场景化菜单让玩家第一眼就理解“从哪里进馆、在哪里补给”，也让封面成为叙事的一部分。
- 影响：换封面构图时需同步调整 `title_screen.tscn` 里的 640×360 坐标；按钮仍是标准 `Button`，键盘/鼠标与输入流测试照常覆盖。
