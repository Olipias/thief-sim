# M1：确定性路线预演灰盒

状态：2026-11-16采纳的技术方案，待开发。仅文档同步。取代“先完成安全屋再验证预演”的顺序及随机巡逻偏移/近似预测承诺。

## 模拟约束

- 固定步长（建议20 tick/s，最终频率由灰盒验证确定）；模拟状态与渲染解耦。预演和执行使用同一状态转换、碰撞、视线与事件代码，不允许预演估算而实际执行依赖另一套物理移动。
- 巡逻路点和停留时长构成时间轴，按模拟tick计算位置/朝向；发现、调查、追击使用确定性状态机。监控按固定周期摆动，不依赖渲染帧率。
- 地面材质与动作生成带ID、tick、位置、半径和来源的噪音事件，按固定顺序确定受影响守卫及调查行为。明确视线遮挡、多个事件优先级、同时发生时的处理次序。
- 默认不使用随机数。确需随机因素时，只能用可复制的固定种子和完整随机状态，纳入快照；同快照/输入必须完全一致，不允许执行时添加随机巡逻偏移。
- 玩家点选路径节点，可附等待N秒、蹲行、开锁、拿取动作，全部转换为整数tick时间轴；动作前置条件和失败事件也共享同一模拟规则。

## 快照、预演、执行和回退

- 规划时冻结整个世界。快照包含玩家/守卫状态及计时、监控相位、噪音、门锁、物品、行动时钟和必要的随机状态；预演只修改快照副本。
- 不渲染地向前运行路线模拟，输出逐tick记录。用玩家半透明轨迹、守卫残影及黄色首次发现预警展示；这是路线可视化，不是文物幽灵系统。
- 执行从同一快照开始，渲染逐帧读取模拟；记录逐tick完整状态、动作、事件和必要的渲染帧对应关系。
- 发现时定位实际触发tick及帧，红色高亮具体守卫/监控视锥或噪音事件，不能按当前守卫状态猜原因。发现同时有多个原因时保留事件列表与稳定的首因规则。
- 失败恢复整份规划起始快照，回到规划界面并保留原路线/动作供修改；不扣命、不清空路线、不出现加载读条。取代只将玩家送回房间入口、其余世界不回退的做法。
- 一致性边界：同快照、同路线、同动作且无手动接管时必须逐tick相同。手动接管改变输入后原预测失效，明确提示；再次规划从新的完整快照重算。若要退出/放弃本次行动，恢复规则与失败重试分开定义。

## 灰盒范围与验收

一个房间、一名保安、一个周期监控、一扇锁门、一件目标；等待、蹲行、开锁、拿取均可验证。先不接完整安全屋、美术与历史剧情。

同一组快照/路线分别预演与执行，对比每个tick的状态摘要、事件顺序、首次发现tick、位置、原因实体/事件ID、门锁与物品变化；要求100%一致，不能只比最终成功/失败。在不同渲染帧率、帧率抖动和重复运行下结果仍一致。失败回退后重复执行同路线一致；修改路线后重新预测一致。另验规划全冻结、所有退出路径恢复、手动接管使预测失效、噪音调查与可见遮挡。

通过灰盒验收后再接入R-01安全屋及完整关卡。旧版test通过不代表此确定性保证已建立。
