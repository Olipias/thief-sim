# OpenCode后续开发执行计划与验收门槛

日期：2026-11-20。本文是当前开发交接；依[确认方案](CONFIRMED_DESIGN.md)、[探索循环](EXPLORATION_LOOP.md)与[任务板](ROADMAP.md)执行。本文写成不代表玩法完成。本轮Codex只交付计划，OpenCode受领开发任务后应实施、验证和导出，不重复写一份计划便收尾。

## 1. 最终需要交出的游戏

玩家从指定封面进入q6开场，自行推进或跳过后开始教学。教学撤离进入可走动的独立安全屋；在实体电脑查资料、连线推理，用手机准备，在门口进入固定展馆。地图随探索揭开，可以不带主目标撤离，卖掉普通战利品，采购道具再进馆。最终取回三件主文物之一，并完成恶魔或对应国家的交付剧情。

正式流程没有旧Hub顶部栏目页。地图、物品、交易、知识和回放状态不会因重进、连点或读档丢失、复制或互相污染。玩家实际使用的预演与执行在同快照、同输入下逐tick一致，失败原因可定位，回退保留路线。

本计划采用最新裁定，不恢复全馆倒计时、旧144秒CG、三链齐全才出发、局外完整目标照片、六件混淆模型、文物器灵或主要文物普通出售。10–12区域、2–4趟仍是可调设计目标，不是硬性凑数门槛。三人盲测与30–50分钟体验必须据实记录。

## 3. 分批实施与过关标准

各批在ROADMAP登记子项及证据链接。批次通过后继续下一批；没有通过时修当前批，不以扩大地图或增加道具回避核心问题。

### 批次A：真实关卡的确定性与完整回退（R-02补齐）

沿用现有内核，在一个实际可玩的房间接通权威模拟、真实输入、渲染与事件记录。实际有几名守卫/监控就纳入几名，缺席实体不能由默认快照补出假守卫。明确碰撞/遮挡、动作前置条件、多个事件同时发生的稳定顺序；消除预演和实际移动的双重推进。

必须达到：

- 鼠标点路点，界面可为节点设置等待、蹲行、开锁、拿取；错误位置/缺条件有明确反馈。不能只有逻辑函数支持动作，玩家却无法操作。
- 固定tick下，无手动接管时，预演副本与实际场景执行的每tick完整状态、事件顺序、首次发现tick、实体ID与原因一致；比较不能只测simulate_route两次或只比最终成败。
- 覆盖安全路线、守卫视线、墙体遮挡、摄像头、材质/动作噪音调查、门锁和拿取；至少含多守卫/多监控的场景用例后才允许扩图。
- 在30/60/120渲染帧率及抖动调度下重复验证；这些是测试配置，不承诺所有硬件性能。精确规则状态相同，插值画面不参与判定。
- 失败红色标出真实触发实体/视锥或噪音事件；恢复玩家、全部守卫状态与计时、监控、门锁、物品、背包、烟雾与消耗量，保留路线和动作；相同路线再执行得到相同结果。
- 规划期间移动、拾取、消耗道具均无效；所有退出路径一起恢复。手动接管使旧预测失效，再开规划从新快照预测。

证据：真实场景输入测试、逐tick差异报告（零差异）、完整快照回滚比较、原因ID断言、截图/操作录像。保留test_planning_freeze专项，纳入本批实际检查。先过此批再开发更大的关卡，不重复重做已通过的纯灰盒。

### 批次B：4–5区域探索与跨次记录样板（R-11a/R-13a）

通过生成器创建固定布局，至少包含入口、普通展厅、资料点、主展厅及服务连接/出口功能；小样板暂只接一条主目标线，不能冒称三目标齐全。设计两条可选路径、一个可回开的捷径和明确地标。

必须达到：

- 首次地图只显示已探区域；未知房框、目标/出口标记、全图尺寸、悬停、路线寻路和预演均不泄密。读布展单只增加“待找地点”，实地对应门牌才能定位。
- 房间、门、线索用稳定ID。正常撤离再进、退出游戏继续、旧档迁移均正确；未找到线索不能因加载地图自动获得。
- 空手与普通战利品均可正常撤离；普通货物入库，不直接卖钱，不触发主目标交付。教学面具仍按教学要求，mission_complete不伪设为true。
- 主动放弃没有未带出收益；免费回放恢复物理状态，知识可保留；钥匙和永久捷径在正常撤离后提交，不凭知识复制实物。
- 同一普通实例不能同时在馆内、背包、仓库；已经带出的不会重生。可只做一件主目标，但必须允许当趟核对后直接取得，无强制回电脑或跑满次数。
- 规划只编辑已探可走区域；未知风险不显示“确定安全”，内部确定性不因遮雾而改变。

证据：一次探索→撤离→重进→读档的真实键鼠流程；地图前后截图；缺字段/脏档；带出/放弃/回放的物品与知识对照表。开发中可以暂用旧入口测试，但旧Hub不能算此后完整闭环的合格入口。

### 批次C：独立安全屋和手机出发（R-01/R-04骨架）

安全屋作为独立Node2D世界场景，包含可走动角色、碰撞墙体、书桌电脑、箱子、房门及基本室内布置。设备界面由交互触发；复用现有可用资源，先把场景和输入做完整。

必须达到：

- 新游戏→q6自动/手动/Skip→教学→安全屋可操作；继续、正常撤离、放弃、结局返回/回溯均到合法场景。正式流程无法进入旧Hub栏目。
- 走到电脑按E打开，ESC逐层返回后回桌旁；房内不能穿墙、穿家具。世界不挂CanvasLayer。
- 手机选侦察或目标只准备，关闭手机仍在房间；走到门口确认才出发，取消不切场景；出发与交货不串动作。
- B/P/ESC和对话、电脑、手机、规划的暂停原因正确叠加；关闭一层不误恢复其他层，打开设备的E不穿透为拾取/出门。
- 标题继续读取新旧合法存档；不存在存档时继续状态正确；指定封面与q6时序不退化。640×360所有可见文字与按钮无越框。

证据：真实输入完整场景流、碰撞测试、覆盖层不变量、新游戏/继续截图、按MANUAL_QA实际检查。此批结束必须让用户能看见并走进安全屋，静态背景截图不算通过。

### 批次D：普通交易、采购与再次探索（R-05/R-12a）

接通箱内/随身转移、手机预约、门外神秘人验货付款；安全屋手机增加采购与备货配装，先复用烟雾与跑鞋实际功能。

必须达到：

- 从游戏内带出普通货物→存箱→预约→取货→门口交货→收钱→手机购买→下次携带→进入同一展馆实际使用，全程通过UI完成。
- 预约不扣货、不发钱；缺货、取消、重复确认、快速连点、读档恢复不丢货或重复付款。箱内/随身/馆内/已售实例所有权唯一。
- 采购一次确认扣款/发货一次；库存与携带数量分开，烟雾为消耗品，跑鞋实际效果和文案相符；馆内不能即时购物。
- 购买、交货、撤离事务在保存前后中断恢复时不会出现半扣款或重复收益；定义原子提交/恢复策略并测试。
- 主文物不能进入普通报价、预约或交货；钱包为零、工具耗尽仍有主线可达路线。失败回放不回滚之前在住处完成的交易。

证据：完整闭环录像/真实输入、交易幂等与事务恢复测试、账目不变量、旧仓库字符串数组迁移测试。只把商店改名成手机不算通过。

**第一份应交给用户的闭环包：A–D全部通过。** 包里允许主展厅与剧情尚未铺满，但必须能反复探索、正常撤离、进入安全屋、出售、采购再出门，并明确剩余范围。

### 批次E：电脑、调查玩法与直白剧情（R-03/R-04/R-09/R-10）

按[叙事V2补丁](narrative/EXPLORATION_PATCH_V2.md)覆盖V1冲突段落。实现浏览器关键词查资料、档案阅读与附件、邮件往返、聊天追问；每个应用至少有一条实际改变调查信息的交互链，不能换壳显示同一份全部线索列表。手机联系人与日历承载人物关系、来信或预约记录，不做装饰空页。

必须达到：

- 起步是文字档案/特征，未见实物没有完整目标照片；探索获得的门牌、布展单、柜号与观察逐步进入板面。
- 玩家真实拖卡、连线、选择关系；错误有针对材料的反馈，正确只解决当前问题，不自动完成整条链。能修正错误，存读档保留材料与已确认关系。
- 至少有一条完整谜题要求联合两份不同来源的材料，排除一个有理由但不成立的解释，并据结论决定下一处探索；不能仅靠两张同名卡配对或按提示逐项点击。
- 三条线不互相强制门禁；现场已核对目标可当趟取物。历史知识确实参与判断，不能把材料里的考古地点当游戏当晚位置。
- 读档不会先说“收到照片”再让玩家首次拍照；普通侦察回来不进入主目标催交。每段说明说话人身份、与玩家关系或下一步所需信息。
- 逐段事实ID映射，件目/同类资料不混用，未知不升级为事实；恶魔全分支单独审校。stop-slop、Humanizer-zh实际读取和检查后记录来源与修改，不照抄“已审”结论。
- 声明集中标题，来源可查；正篇不显示作者标签/代码ID；历史边界测试保留并改测元数据、自然归因及声明映射。
- 未获确认的死亡代价等提案单列待裁定，继续其他已授权功能，不自行确定不可逆剧情后果。

证据：至少一条从阅读资料→探索→回看→错误关系→修正→定位的真实输入录像/测试，分页截图与文本审校表。其余两条在正式交付前同样跑通；新剧情未审部分明确隔离，不能把全稿自动视为已确认。

### 批次F：扩大展馆、三个主目标与交付分支（R-11b/R-12b/R-06）

在样板基础上扩展至设计目标约10–12区域；根据实际试玩调整数量。三主展厅分布于不同支路，使用现有三件指定素材；增加一类维护门工具捷径，同时保留免费钥匙/调查通路。

必须达到：

- 三件主目标在同一固定地图中各有实际位置，手机切追踪不交换、复制或重新生成。一次只带走一件完成本章；另外两条线未完成不阻塞。
- 每条支路都有可辨地标、推进材料或收益，至少一条回路减少重复走路。全地图每种门/巡逻/工具机制继续满足A批规则。
- 每个目标从新档或合法测试起点可达；测试状态注入只能辅助分支覆盖，至少一次完整通关从新游戏走正常UI。
- 各目标分别验证直接交恶魔、拒交后屈服、拒交后交对应国家；目标存箱后仍可触发与交付，重复点击/读档不重复消费，不能普通卖掉或继续刷主目标。
- 结局、检查点回溯与普通读档的范围明确：回溯恢复一致的整份合法状态，不把未来货款/物品带回旧节点造成复制。

证据：三目标×三交付路径的覆盖表、完整新游戏记录、可达性/实例唯一/存档测试、全部新增区域截图。剧情代价待裁定时相关结局标待确认，其余路径继续验证。

## 4. 每批共同的工程门槛

1. 逻辑用例进入现有逻辑/进度测试；UI必须通过InputEvent真实按键/鼠标事件驱动，不能只调open/close。新增独立测试须挂入验证入口或作为明确必跑命令，不能写好却从不运行。
2. 新存档字段必须测缺字段老档、脏类型、非法ID、重复实例、读写往返、迁移重复执行；保留未来档策略，不能静默改旧字段语义。
3. 资源非负、实例唯一、主目标状态一致、暂停原因一致、规划冻结一致等持续规则加入monkey。测试隔离/tmp存档，不污染用户试玩记录。
4. 每批最终全量verify通过；画面改动补visual。引擎错误/警告/泄漏按既有门禁处理，不放宽允许清单。改设计导致旧断言不适用时，以新行为测试替换并解释，不删覆盖范围。
5. 更新CHANGELOG、README、ROADMAP；涉及数据流/迁移更新ARCHITECTURE/DECISIONS，生成地图改脚本再生成。源码、素材、许可登记与发布包一致。
6. 阻塞记录具体命令、退出码、日志位置和影响范围。长时间无输出时先查当前步骤子日志/进程，不反复套300秒timeout重试截图；截图需渲染环境，使用仓库visual入口。

## 5. OpenCode每批交付格式

在docs/qa/为该批保存原始命令日志、版本/提交或工作区差异标识、截图、测试矩阵与可运行包位置。测试矩阵逐项写“要求→操作/输入→预期→实际→证据→状态”；状态只用通过、失败、待实现、待真人验证、环境阻塞。

最终回复包括：本批用户可见变化、运行方法、实际检查结果、对应ROADMAP状态、剩余工作及下一批。不得只报告改了多少文件、测试总数或“全部完成”。

| 交付等级 | 可以宣称什么 | 必须具备的依据 |
| --- | --- | --- |
| 小样板通过 | 可重复潜入的探索技术样板 | A、B的真实场景/回退/迷雾/撤离证据 |
| 核心循环通过 | 可玩的安全屋—探索—交易—采购循环 | A–D全通过，独立导出包与完整UI流程 |
| 功能交付通过 | 当前设计的功能均已实现 | A–F、自动/视觉/手测及全部主目标分支通过 |
| 完整验收通过 | 功能与体验均满足目标 | 上述全部，加真人记录、时长、知识理解与问题复测 |

当前全部后续批次均待实施/专项验收。11月19日的16项回归绿灯只证明当时旧实现测试通过，不能填进上述新增项的“实际结果”。
