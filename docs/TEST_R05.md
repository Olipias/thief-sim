# R-05 普通战利品交易验收矩阵（test）

> 依据：`docs/OPENCODE_NEXT_PLAN.md` 批次 D、code #647 的 R-05 实现口径。
> 归属：`src/ui/box_screen.gd`、`mission_phone.gd`（trade App）、`main.gd`、`safehouse.gd`、`game_state.gd`、`delivery_screen` 由 code 负责；
> `tests/**` 由 test 负责。代码字段/API 落定后本矩阵转成可执行用例，避免提前写入 red parse error。

## 1. 数据与存档（`tests/test_save_compat.gd`）

- [ ] 老档缺 `loot_reserved`：加载为空，不崩溃、不发钱、不吞箱内/背包物品。
- [ ] 脏类型：`loot_reserved` 为字符串/数组/嵌套字典/非法 instance_id：忽略非法项，合法项去重保留。
- [ ] 背包条目 `reserved` 缺省 false；脏类型按 false；预约/取消/交货后往返一致。
- [ ] 读档不会把已售/已交货实例重新放回箱内或背包。
- [ ] 未来字段保留（新键往返不丢）。
- [ ] 预约记录与 `loot_stash`/`bag_items` 的实例所有权唯一：同一 instance_id 不能同时在箱内、背包、已预约、已售。

## 2. 进度与结算（`tests/test_progression.gd`）

- [ ] 预约：不扣货、不发钱；物品标记 `reserved` 并从可交易列表移除；取消恢复，金币/箱内数量不变。
- [ ] 门口交货：确认一次 → 金币只加一次，箱内/背包对应实例只消费一次，`loot_reserved` 清空。
- [ ] 重复确认/快速连点/重复打开交货页：不重复扣货或加钱。
- [ ] 交货后读档再交货：无货可交，不重复发钱；已售实例重进馆不刷新。
- [ ] 撤离/侦察回安全屋后预约状态保留；主文物（双羊尊/圣甲虫/注壶）不可进入普通报价、预约或交货。
- [ ] 钱包为零、工具耗尽仍有主线可达路线；普通交易失败不回滚已有主线状态。

## 3. 真实输入流（`tests/test_input_flow.gd`）

- [ ] 箱界面：随身↔箱内转移；转移后实例只在一侧；B/ESC 关闭并恢复暂停。
- [ ] 手机交易 App：预约/取消/重复确认；预约后箱内该件不可再次预约；关闭手机仍在安全屋。
- [ ] 房门：有预约货或未存箱物时 E 不得出发并提示先交货/处理；交货确认面板列出清单与总价。
- [ ] 交货确认：E/按钮一次收款；B/P/ESC 逐层关闭；关闭后回安全屋，不误触出发。
- [ ] 交货后再次走到门口可正常出发；已售实例不会在馆内重新生成。
- [ ] 640×360 箱/交易/交货面板文字不越框；无买家倒计时/读秒。
