# Loop 1：Agent 协作与显著进展

本页整理 `#thief` 共享频道中各 agent 的真实协作记录，证明多 agent 并行完成的设计决策、实现批次与验收结果。所有摘录均来自 `agentchattr` 可读的历史消息，未编造会话 ID 或时间。

## 协作角色

- **plan**：统筹设计校准、任务派发、ROADMAP 更新。
- **code**：核心 gameplay 实现（博物馆、预演系统、存档、UI）。
- **test**：测试用例、回归验收、缺陷定位。
- **art**：美术资源、图标、UI 素材。
- **codex**：开场 CG q6 六格分镜（v0.23.0）。
- **opencode**（本窗口）：标题 UI 重排、规划冻结修复、打包（v0.23.1）。

## 关键设计决策（来自真实讨论）

### 1. 移除幽灵 / 器灵 / 鬼魂哀嚎机制

plan 在 #463 中明确：

> “彻底移除文物幽灵 / 鬼魂哀嚎 / 器灵对谈机制……博物馆内的展签和游客留言也去掉‘左羊/右羊低语’，只保留纯客观展签卡、游客留言与主角观察旁白。”

后续 code 在 v0.20.0 中执行了该裁剪，test 同步清理了相关断言。

### 2. 核心玩法改为“路线预演 + 失败回放”

plan #463 同时锁定：

> “核心玩法锁定为「路线预演（规划—执行—失败回放）」+「零倒计时」……被发现时不判 Game Over 扣命，而是回放到失败节点，用红色高亮标出被发现原因。”

这一机制在 v0.20.1 落地，v0.20.3 修复鼠标坐标转换、安全回退点、零器灵残留，v0.22.0/v0.22.1 升级为确定性预演灰盒。

### 3. 三件主要文物走剧情交付，普通文物走预约交易

来自用户原话摘录（已收入 QA.md）：

> “三件主要文物是走剧情的，要么上交给恶魔要么给对应国家，其他普通文物 app 上即可出售。”

plan 将其拆分为 R-06 剧情交付与 R-05 箱子预约交易，当前 R-06 逻辑骨架已存在，R-05 仍待实现。

## 真实协作模式示例

plan 派发任务 → code 实现 → test 独立复核并发现缺陷 → code 修复 → test 再验证 → art 待命配合。例如 v0.20.3 流程：

1. plan #508 列出 v0.20.3 必须修复的 5 项细节。
2. code #511 回复“收到，开始执行”。
3. test #513 提前补上红测试，明确验收标准。
4. code #515 提交修复，跑 --visual 更新基线。
5. test #517 独立复核，确认核心 P0/P1 通过，并提出 5 个 P2/规格差异。
